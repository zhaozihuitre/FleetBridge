# 舰桥 Web 版：平板 / 其他设备用浏览器操作（方案）

2026-11-06。**只是方案，还没有改代码**。涉及开放端口和局域网暴露，确认后再动手。

---

## 1. 现状

### 两个服务

| | 主服务（指挥中心） | 手机服务 |
|---|---|---|
| 监听 | `127.0.0.1:8787`（开发实例 8790） | `0.0.0.0:8789`（主端口 + 2，可用 `MONITOR_MOBILE_PORT` 改） |
| 谁能连 | 只有本机。另外检查 Origin，只接受 `http://127.0.0.1:8787` / `localhost:8787` 的页面请求和终端 WebSocket | 只接受私有地址：10/8、172.16/12、192.168/16、169.254/16、Tailscale 100.64/10、本机 |
| 鉴权 | 没有（只靠「只在本机」） | PIN（默认 `123456`，4~12 位数字，scrypt 存储），或电脑上二维码里的随机 key。登录后发 30 天的设备 cookie（HttpOnly、SameSite=Lax，服务端只存哈希）。输错 5 次按 IP 锁定 5 分钟，之后加倍到 1 小时；全局 10 分钟内错 30 次，全部锁 10 分钟 |
| 能做什么 | 全部 | 手机页（`/m`）：看部队、看终端屏幕（文字快照，非实时终端）、发文字、回答授权和提问、按几个键（Esc ↑ ↓ Tab ⏎ 1 2 3）。不能启动或结束终端，不能改设置，不能直接往终端里打字 |
| 默认 | 开 | 关，在「手机访问」里打开 |

### 回答「局域网里的其他设备能不能访问」

- **指挥中心本身（完整界面）：不能**。它只监听 127.0.0.1。`fleet-bridge --headless` 也只是在本机浏览器里用。
- **手机页：能**，前提是在指挥中心里打开了「手机访问」。用浏览器打开 `http://<电脑IP>:8789/m`，输入 PIN 即可。平板也能用，但只是手机页那套有限的功能。

### 这台电脑的实际情况（需要注意）

- 手机访问**现在是开着的**，`0.0.0.0:8789` 正在监听，已有 4 台设备登录过。
- **PIN 还是默认的 `123456`**。同一网络里任何人只要知道默认值就能登录，锁定机制拦不住一次就猜中的默认 PIN。
- 当前网络在 Windows 里是「公用」类型（可能是公司或公共 Wi-Fi）。HTTP 明文传输，同一网络的人可以抓到 PIN 或 cookie。

**建议不论方案做不做，都先在「手机访问」里把 PIN 改掉。**

## 2. 方案

> **2026-11-06 修订（用户意见）：** 平板上的操作和电脑上一样，用同一个 Web 界面。不做专门的触屏交互，也不做单独的平板布局。平板这边只做到「在平板浏览器上能正常显示和操作」；重点放在**默认启用 Web** 和**访问鉴权**。

### 2.1 总体：局域网端口提供和电脑上相同的指挥中心

- 局域网端口仍是 **8789**（不新开端口）。
  - `/` 是和电脑上**完全相同**的指挥中心页面。
  - `/m` 保留手机页（手机屏幕太窄，完整界面用不了）。
- 主服务 `127.0.0.1:8787` **不变**：Electron 外壳和本机浏览器照旧免登录，外部仍连不上。
- 实现方式：局域网服务对已登录的请求，转发到主服务同一套处理函数（不另写一套 API）。转发前**按白名单放行**（见 2.3），并把 Origin 检查改为「同源 + 已登录」，不再要求必须是 127.0.0.1。
- 终端 WebSocket（`/ws/agents/<id>`）也走局域网端口，用同一个 cookie 鉴权，Origin 必须是本服务自身的地址。
- 页面里只在 Electron 才有意义的东西（窗口的最小化 / 最大化 / 关闭按钮、弹出独立窗口）在浏览器里隐藏或改成「新标签页打开」。headless 版本已经是这样处理的，沿用即可。

### 2.2 「默认启用」怎么做：两种做法，需要你选

| | A. 安装后自动开启 | B. 默认开，但第一次要在电脑上设好口令才真正监听（推荐） |
|---|---|---|
| 首次启动 | 立刻在 `0.0.0.0:8789` 监听 | 指挥中心弹出「Web 访问」引导：设置口令，确认后才开始监听；跳过就保持关闭，以后可在设置里打开 |
| 默认口令 | 必须随机生成（显示在电脑上） | 没有默认值，必须自己设 |
| 风险 | 用户还不知道有这个功能时，端口就已经对局域网开放了 | 端口只在用户明确同意之后才开放 |
| Windows 防火墙 | 首次监听时 Windows 会弹窗询问是否允许访问网络；点了「取消」就连不上，而且很难察觉 | 同左，但弹窗出现在用户刚点了「开启」之后，用户知道是怎么回事 |

**推荐 B**。体验上同样是「默认开」：首次启动就引导打开。但不会出现「装完就暴露在公司 Wi-Fi 上」。

### 2.3 鉴权和安全（不论 A / B 都要做）

1. **废掉默认 PIN `123456`**。
   - 口令至少 8 位，数字或字母都可以。
   - 现有只设了默认 PIN 的手机，升级后需要重新设口令。
2. **新设备首次登录需要在电脑上点「允许」**（推荐，默认开）。
   - 口令正确后，电脑上的指挥中心弹出「新设备请求访问：Android / Chrome，来自 192.168.x.x」→ 允许 / 拒绝。
   - 口令被偷看或抓包也进不来。代价是每台新设备第一次登录时要回到电脑前点一下，之后 30 天免登录。
3. **设备管理**：在电脑上列出已登录的设备（类型、最后使用时间、IP），可以单个踢掉，也可以全部登出。现在只能「全部登出」。
4. **权限**：局域网设备和电脑上一样是完整控制（按你的意见，操作和电脑一致）。如果以后需要「只读」设备，再加一档。
5. **局域网永远不开放的接口**，只能本机调用：
   - `/api/admin/*`（退出、升级、回滚）。
   - Web 访问 / 手机访问的设置本身（改口令、开关、设备管理），防止局域网设备改掉口令或放行别的设备。
   - `POST /api/preview`：让电脑打开任意本地路径做预览。局域网设备只能看电脑上已经打开的预览。
   - 主控 MCP 专用的接口（`/api/ui`、`/api/ui/done` 等）。
6. **会话 cookie** 改为 `SameSite=Strict`；所有写操作检查 Origin（同源），防止局域网里别的网页借用 cookie 发请求。
7. **只允许私有地址**：保留现在的检查。即使路由器把端口转发到公网，也拒绝公网地址。
8. **HTTP 还是 HTTPS**（取舍，需要你选）：
   - **HTTP（推荐先这样）**：简单，平板直接能用。在公用 Wi-Fi 上口令和 cookie 是明文，由第 2 条「电脑上点允许」兜底。设置页提示「在不信任的网络上请用 Tailscale」；Tailscale 是加密隧道，现在就支持。
   - **HTTPS + 自签证书**：传输加密，但平板浏览器会有证书警告，要手动信任（iPad 还要装描述文件）；终端 WebSocket 也要改成 wss。可以以后再做。
9. **审计**：局域网设备发出的指令，在「指令」记录里标来源「Web · 设备名」；新设备登录、被拒绝、被踢都记一条。

### 2.3b 同一个地址 / 二维码，按设备分流（用户追加，0.9.39）

- 平板、电脑、手机用同一个地址和同一个二维码（二维码只是地址 http://<IP>:8789/，不带任何密钥）。
- 登录后按设备自动进页面：手机 → /m 手机页；平板、电脑 → / 完整指挥中心。判断以屏幕为主（触屏 + 屏幕短边 < 600px 算手机），User-Agent 辅助；iPad 默认 UA 伪装成 Mac：Macintosh UA + 多点触控 算平板。
- 两个页面都有手动切换（完整版顶栏「手机版」、手机页右上「完整版」），选择记在本机（localStorage fb-view），之后打开同一地址按这个选择。
- 扫码仍走同一套鉴权：先在电脑上设口令，新设备首次登录要在电脑上点「允许」。0.9.35 起二维码里带的免密登录密钥已取消（旧链接打开只看到登录页）。

### 2.4 两台设备同时看一个终端（必须处理）

这不是平板适配，而是 Web 版一打开就会遇到的正确性问题：

- 同一个终端只有一个真实尺寸（行 × 列）。现在每个连上的页面尺寸一变就发 resize。平板一打开某个终端，电脑上的同一个终端就会被改成平板的宽度，Claude Code 的界面会按平板宽度重画，反过来也一样。
- **做法**：终端尺寸只跟随「最后一次输入或获得焦点的那一端」。其他端不发 resize，按比例缩放显示（或者横向滚动）。在哪边开始打字，尺寸就切到哪边。

### 2.5 平板上的验证（不做专门适配）

在平板浏览器上（Android Chrome、iPad Safari）打开完整界面，确认下面几项能用；只修有问题的，不做专门的触屏交互：

- 页面完整显示：横屏的平板一般 1180~1366 宽，接近电脑布局的下限，主要看顶栏和标签页有没有被截断。若被截，用美化建议第 11 条的方法（窄屏下压缩顶栏、标签页）修一下。
- 点按钮、切标签页、拖动分隔条（已是 PointerEvents，触屏应该可用）、翻页。
- 终端里能用软键盘打字，中文输入法能上屏，回车能发出去。xterm.js 在触屏上的输入法支持有已知的问题；如果中文上屏有问题，最小的修法是终端下加一个普通输入框，整段发送（和总指令台的输入框一样），不做别的触屏改动。
- 总指令台（主控终端 / 输入框）能下指令。

工具：先在电脑浏览器里用平板尺寸（如 1180×820、820×1180）跑一遍；最后需要你用真实平板试一次（软键盘行为只有真机才能确认）。

## 3. 工作量和顺序

| 步骤 | 内容 | 工作量 |
|---|---|---|
| 1 | 鉴权加固：去掉默认 PIN、口令规则、电脑上确认新设备、设备列表和单个踢出、SameSite=Strict、本机专用接口白名单 | 1 天 |
| 2 | 局域网端口提供完整指挥中心：转发和白名单、终端 WebSocket 鉴权、审计来源、浏览器里隐藏 Electron 专用按钮 | 1 天 |
| 3 | 默认启用和首次引导（方案 B），防火墙提示说明 | 半天 |
| 4 | 终端尺寸跟随操作端 | 半天 |
| 5 | 平板浏览器验证，只修显示不全或不能操作的地方 | 半天 + 真机 |
| 6 | 测试：鉴权的单元测试（错误口令、锁定、cookie、Origin、本机专用接口在局域网被拒绝、未确认的设备被拒绝） | 包含在 1~2 中 |

合计约 3~3.5 天，分 2 个版本发布：1+2+3（默认启用 Web、安全）→ 4+5（多端同时使用、平板验证）。
