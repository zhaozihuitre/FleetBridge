## P0 安全

### A1 手机访问还在用默认 PIN

- **现状**：正式版手机访问已开启，PIN 仍是默认 123456，已有 3 台设备登录（30 天有效）。界面上只有一行提示。连续输错会锁定，但默认值谁都知道，同一 Wi-Fi 下的人可以登录，看屏幕、给 agent 下指令、回答授权。
- **改法**：PIN 还是默认值时，手机端不接受登录，只显示「请先在电脑上修改 PIN」；开启手机访问时强制先设 PIN。已登录的设备保留。
- **工作量**：XS。**风险**：低；已经登录的手机不受影响。也可以先让用户自己在「手机访问」面板里改一次（立刻生效）。

### A2 本机 API 不检查 Host（DNS 重绑定）

- **现状**：`127.0.0.1:8787` 拒绝带外来 `Origin` 的请求（所以网页无法用 POST 控制 agent），但普通 GET 不带 `Origin`，也没有检查 `Host`。恶意网页可以把自己的域名解析到 127.0.0.1（DNS 重绑定），然后读到 `/api/state`：账号邮箱、项目路径、最近的指令和回复。预览服务器（8797）同理。
- **改法**：只接受 `Host` 是 `127.0.0.1:端口` 或 `localhost:端口` 的请求，其余 403。手机服务器不受影响（它有自己的登录）。
- **工作量**：XS。**风险**：很低。

### A3 主控的指令和用户亲手输入无法区分

- **现状**：`fleet_send` 把文字直接打进 agent 的 Claude Code，和用户亲手输入一模一样。agent 只能靠主控自觉加的「（主控转达…）」来分辨。主控也可以打出「确认发版」这样的文字，agent 无法分辨是不是用户本人。
- **改法**：服务端给所有来自主控的输入加上固定前缀（例如「【主控】」），主控无法省略。agent 的系统提示里写明：带这个前缀的不是用户本人。这也是 B5「待确认」面板的前提：用户本人的批准走另一条通道。
- **工作量**：S。**风险**：低；主控指南需要同步改。

### A4 装一次新安装包（用户操作）

- **现状**：就地升级只换 server/ 和 web/。外壳还是 0.9.14，缺少后来的外壳改动：与 npm 版互斥的检查、`fleet-bridge stop`、清理旧版本文件夹时跳过占用中的文件夹等。
- **改法**：用户运行一次 `dist/FleetBridge-Setup-0.9.26.exe` 覆盖安装。注意：覆盖安装会结束正在运行的终端（安装程序要替换同名进程），会话可以在存档里接着用。
- **工作量**：XS（用户操作，约 2 分钟）。

## P1 主控工作流

### B1 被打断的一轮也报「完成」（第 2 项，属实）

- **现状**：`server/turns.js` 只看「agent 开始忙过、现在空闲了」就算这一轮结束，并取最后一段回答，不区分正常结束和用户打断（Esc、/login 等）。所以会发出「完成」，还带着之前的旧回答。
- **改法**：读 transcript 时检查这一轮里有没有 `[Request interrupted by user` 的记录，有的话通知改成「被中断」，不带回答。
- **工作量**：S。**风险**：低。

### B2 同一个授权框重复通知（第 3 项，属实，原因已定位）

- **现状**：`master.js` 用「agent → 问题指纹」记录已经通知过的问题，但只要某一次轮询没在屏幕上识别到这个问题（屏幕重绘、滚动的一瞬间），记录就被删掉，下一次识别到时又当成新问题发一遍。rm -rf 那次的 3 次就是这样来的。
- **改法**：问题消失后保留记录 30 秒再删；指纹只用稳定的部分（类型、选项、命令的第一行）。
- **工作量**：S。**风险**：低。

### B3 长指令显示成 `<pasted_content id=…>`（第 5 项，属实，范围更大）

- **现状**：用户粘贴的长文本在 transcript 里被包成 `<pasted_content id="…">…</pasted_content>`。`lastPrompt` 原样取开头，所以 fleet_status、部队卡片、小窗、手机页都只显示 `<pasted_content id="eebf">`（截图里能看到）。
- **改法**：在服务端解析 `lastPrompt` 时去掉这层包装，显示里面内容的第一行，加「（粘贴）」标记。所有显示位置一起生效。
- **工作量**：S。**风险**：低。

### B4 升级后主控的工具是旧的（第 4 项，属实）

- **现状**：主控启动时把 `fleet-mcp.cjs` 复制到自己的目录，并带上固定的 `--allowedTools`。就地升级不会动正在运行的主控，所以新工具（例如 fleet_open）要等主控重启才有。
- **改法**：
  - **先做（S）**：升级后比较主控用的工具脚本和新版本的，不同就在主控栏显示「主控工具有更新 · ↻ 重启主控」，并在通知里告诉主控。
  - **以后（M）**：fleet-mcp.cjs 改成薄代理，工具清单从服务端取，升级后发 `tools/list_changed` 让 Claude Code 自动刷新；`--allowedTools` 改为按 MCP 服务器整体授权。需要先确认 Claude Code 对 list_changed 的支持。
- **风险**：先做的方案低；自动刷新方案中。

### B5 「待确认」面板（第 1 项，可行，依赖 A3）

- **现状**：推送、发版这类事要用户本人在 agent 终端里确认，用户必须找到那个终端打字。
- **改法**：
  - 给我方 agent 一个只能「提出」确认请求的工具（例如 `ask_user_confirm(摘要, 将执行的命令)`），请求出现在指挥中心和手机页的「待确认」列表里。
  - 用户点「批准」或「拒绝」，服务端以用户身份把「确认：<摘要>」打进该终端，并带上用户通道的标记。
  - 主控的工具里没有「批准」，主控也无法伪造（A3 的前缀保证）。
- **工作量**：M（1–2 天）。**风险**：中，涉及「谁有权批准」，要把边界写清楚、测清楚。

### B6 舰桥队列和 SendMessage 不互通（第 9 项，属实）

- **现状**：`fleet_send` 发给忙碌中的 agent 时，指令进的是舰桥自己的队列（queues.json），这一轮做完才打进去；agent 在这之前完全看不到它，名称问题那次就是这样。主控说的 SendMessage 是 Claude Code 自己的消息通道，两边互不相通。
- **改法（二选一）**：
  - a. 默认改为直接打进去：Claude Code 本身支持在忙碌时接收输入，会在下一次工具调用之间读到。这样 agent 能更早看到，但可能改变它这一轮的做法。
  - b. 保留队列，`fleet_send` 和 fleet_status 写清楚「已排队：对方这一轮结束后才会看到」，主控指南里同步说明。
- **工作量**：S。**风险**：a 中（行为变化），b 低。建议 b，紧急的事用 mode "now"。

## P2 体验与质量

### C1 上下文超过 80% 时提醒（第 7 项，已有，补通知）

- **现状**：已经有：上下文 ≥ 85%（`config.thresholds.contextWarnPct`）时，指挥中心和小窗出「记忆负载 X%，执行 /compact」的提醒。但主控不知道，手机页去掉消息后也看不到。
- **改法**：阈值改为 80% 并可配置；每个会话越过阈值时通知主控一次。
- **工作量**：XS。

### C2 用户亲手下的指令做完也通知主控（第 6 项）

- **现状**：只跟踪主控发出的轮次（`turns.js` 里 `noteOrder` 只记 `master`）。
- **改法**：加开关「用户亲手下的指令做完也告诉主控」，打开后同样跟踪，通知里只带摘要。
- **工作量**：S。**风险**：主控收到的通知变多、占用它的上下文，所以默认关。

### C3 测试会话自动清理（第 8 项）

- **现状**：开发实例的 agent 名字带 `dev·`，但它们的 transcript 留在 `~/.claude/projects`。目前要手动删（还有 9 个等用户确认）。
- **改法**：开发实例记录自己启动过的会话 ID；结束测试 agent 时（或开发实例里的「清理测试会话」按钮）只删这些记录在案的 transcript，删除前列出来。
- **工作量**：S。**风险**：误删真实数据，所以只删开发实例自己记录过的。

### C4 自动化测试（新发现）

- **现状**：没有测试脚本，回归全靠手测。这段时间几次线上问题都可以用小测试提前发现：0.9.13 黑屏、清理版本文件夹 EPERM、提前的完成通知、额度预测。
- **改法**：用 Node 自带的 `node:test` 给纯逻辑部分加测试（turns.js、appdir 的安装 / 切换 / 清理、提示符和对话框识别、手机登录与锁定、npm 版互斥检查），再加一个在测试端口起服务端的冒烟测试；`npm test` 一条命令。
- **工作量**：M。**风险**：无，只加不改。建议排在 D1 之前。

### C5 状态推送太大（新发现）

- **现状**：每次刷新都把整份状态（现在约 108 KB，含 57 条存档、离线项目等）推给每个打开的页面：指挥中心、小窗、弹出终端、手机。手机在 Wi-Fi 下也一样。
- **改法**：存档、离线项目这类很少变的部分单独接口按需取；状态只推变化的部分，或者没变化就不推。
- **工作量**：M。**风险**：中，页面要改取数方式。

## P3 结构与长期

### D1 web/app.js 拆模块

- **现状**：2138 行一个文件（分屏、预览、主控、部队、存档、分隔条……），改一处容易碰到别处。
- **改法**：按功能拆成 ES 模块（panes、previews、operator、units、archive、layout），不改行为。先做 C4 再拆。
- **工作量**：M–L。**风险**：中（纯重构也可能引入回归）。

### D2 空闲 agent 自动休眠（第 10 项）

- **现状**：空闲的 Claude Code 不消耗 token，只占内存（每个约一两百 MB）和一个终端。
- **改法**：空闲超过 N 小时就结束进程，保留会话；下次给它发指令时自动 resume。
- **工作量**：M。**风险**：resume 会重新加载上下文（缓存失效，第一轮更贵），终端里的历史显示会丢。收益小，建议放后面或只做手动「休眠」按钮。

### D3 手机走明文 HTTP

- **现状**：局域网内是 HTTP，同一 Wi-Fi 下能被抓包看到登录 Cookie 和屏幕内容。走 Tailscale 时是加密的。
- **改法**：建议在外用 Tailscale；或者给手机服务器加自签名 HTTPS（手机首次要信任证书，体验差）。
- **工作量**：M。

### D4 其他

- **文档**：README 里还没有手机端新界面、分隔条、npm 版之外的近期功能说明；主控指南（master.js 的 GUIDE）需要跟 A3、B6 一起更新。S。
- **Mac**：见 `docs/npm-install.md` 末尾的清单，需要 Mac 实机。M–L。
- **安装包没有签名**：Windows 首次运行会出 SmartScreen 提示；代码签名证书要花钱，团队内部用可以接受。
- **npm 安装的 allowScripts 提示**：新版 npm 默认不跑安装脚本，第一次启动才下载 Electron。可以在文档里推荐 `--allow-scripts=fleet-bridge`（已写）。
- **GitHub Release**：还差用户执行一次 `gh auth login`。
