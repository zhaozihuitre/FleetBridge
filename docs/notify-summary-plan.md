# 完成通知带总结（方案）

2026-11-06。**只是方案，还没有改代码**。和 `docs/web-access-plan.md`（默认启用 Web）一起确认后再做。

目标：agent 做完（或停下）时，通知里直接写清**做了什么、结论、需不需要你处理**，不用打开终端也知道结果。

---

## 1. 现在的通知渠道

| 渠道 | 谁发、什么时候发 | 现在显示什么 | 长度 |
|---|---|---|---|
| **Windows 桌面通知** | 小窗（`web/widget.js`）在 Electron 里调用系统通知。等授权：立即发；做完：空闲 20 秒后发；负载过高：每个会话每小时最多一次。指挥中心正在前台时不弹。 | 标题「<项目> 做完了，等你指令」；正文是「最后汇报：」加回答的**第一行**（截到 140 字） | 代码里标题截 80、正文截 200；Windows 实际只显示约 3~4 行 |
| **手机推送（ntfy）** | `server/push.js`，规则同上，默认关 | 标题「<项目> 做完了」，正文固定为「等你下一步指令。」。**有意不带任何回答内容**：消息要经过 ntfy 的公共服务器，当初决定只发「哪个项目、发生了什么」 | ntfy 上限 4 KB；手机锁屏折叠时约 2 行 |
| **指挥中心任务列表 + 小窗列表** | `server/state.js` 生成的 quests | 「<项目> 待命，等你下一步指令」+「最后汇报：<第一行>」 | 第一行，140 字 |
| **指挥中心的播报行 / 事件记录** | `state.js` 的 operatorLine、emit | 「<项目> 任务完成，等你下一步指令。「<第一行>」」 | 同上 |
| **手机页** | `/m` 的部队卡片 | 状态 + 回答第一行 | 同上 |
| **主控的【舰桥通知】** | `server/master.js`，只针对主控派出的指令 | 完成 / 中断 / 未执行（0.9.29、0.9.30 新加），附**本轮回答原文**（超过 1500 字截头尾） | 1500 字 |

### 现在的问题

1. **「第一行」经常没用**：回答第一行往往是「好的，我来看一下」「已完成，改动如下：」这类开场白，结论在后面。
2. **需要你处理的情况分不清**：
   - 授权框和 AskUserQuestion 提问框在任务列表、桌面通知、手机推送里**都叫「等你授权」**（都归在 PERMIT 下）。
   - 「做完了但在问你要不要继续」（回答结尾在提问）和「做完了，没事了」显示得一样。
   - 「中断」「未执行」只有主控能收到，桌面通知和手机推送里没有。
3. **手机推送完全没有内容**：这是隐私上的取舍，见 3.4。
4. 主控通知带的是原文，几条通知一起到时很长；开头没有一句话结论。

## 2. 通知分类（先把状态分清楚）

所有渠道用同一套分类和图标：

| 分类 | 图标 | 判断依据 | 标题示例 |
|---|---|---|---|
| 完成 | ✅ | 本轮结束，回答里没有需要你处理的内容 | ✅ pms 完成：价格只受第 1 层两条 SQL 影响 |
| 完成，等你决定 | 🟡 | 本轮结束，但回答里在问你（结尾是问句、出现「要不要 / 是否 / 请确认 / 你选」等），或总结判断「需要用户处理」 | 🟡 newpad 完成，等你决定：要不要推送到远端？ |
| 等授权 | 🔐 | 屏幕上是授权框（Yes / No 类） | 🔐 pms 等授权：PowerShell · Get-ChildItem … |
| 等回答 | ❓ | 屏幕上是提问或选择框（AskUserQuestion、计划确认、0.9.30 新识别的无编号选择框） | ❓ newpad 等回答：Fable 5.1 需要额度 → 切换到 Opus / 申请额度 |
| 中断 | ⏸ | 本轮有「[Request interrupted by user…]」，之后没有再回答 | ⏸ pms 中断：执行到 PowerShell 时被拒绝 |
| 未执行 | 🚫（0.9.43 起；原为 ⛔） | 指令发出后空闲 1 分钟，会话记录里没有任何动作 | ⛔ newpad 未执行：指令没送进去 |
| 额度到限 | ⛔（0.9.43 新增） | 本轮停在额度用完（5 小时 / 周额度、需要 credits）的 API 错误上，或屏幕上是额度/credits 的选择框；写明是哪个组织 | ⛔ monitor：「组织名」额度用完，6pm 重置 |
| 出错 | ❗ | 本轮最后是 API 错误、额度用尽、上下文超限等（会话记录里的错误条目） | ❗ calendar 出错：额度已用完，17:00 重置 |

- 「中断 / 未执行 / 出错」现在只给主控，改为所有渠道都发。
- 「等授权」和「等回答」拆开（现在都叫 PERMIT）。

## 3. 总结怎么生成

### 3.1 三种做法对比

| | A. 规则截取（不调用模型） | B. 调用模型摘要（Haiku） | C. 让 agent 自己在回答末尾写结论 |
|---|---|---|---|
| 做法 | 从本轮最后一条回答里，跳过开场白，取第一句结论；再找「需要你…/要不要…/？」的句子；去掉 Markdown、代码块、表格 | 把指令和回答（截到约 6000 字）交给 Haiku，要求输出固定格式：分类、做了什么、结论、需要你做什么 | 启动 agent 时用 `--append-system-prompt` 要求每次回答最后写一行「结论：… / 需要你：…」，通知直接取这一行 |
| 速度 | 即时 | **实测约 5.6 秒**（本机 `claude -p --model claude-haiku-5-5`，一次短回答） | 即时 |
| 费用 | 0 | 走你的 Claude 订阅（不需要 API key），算进额度。一次约 1~3k token，Haiku 很便宜；按每天 50 次估算，占 5 小时额度的比例很小，但会体现在额度条上 | 0（只多写一行） |
| 质量 | 一般：结构清楚的回答效果好，长篇、表格多的回答容易取偏 | 好：能读懂整段，判断「需不需要你处理」也更准 | 好，而且是 agent 自己的判断。但只对舰桥启动的 agent 有效，外部会话没有；还会改变所有回答的写法 |
| 失败时 | 不会失败 | 超时、额度用完、网络问题、输出格式不对 → 退回 A | agent 忘了写 → 退回 A |

### 3.2 推荐：A 打底 + B 增强（B 可在设置里关掉）

1. 本轮结束时，**先用 A** 立刻生成一个总结。
2. 回答较长（比如超过 300 字）时，同时调用 B（Haiku）：
   - **等最多 15 秒**。拿到就用 B 的结果；超时或失败就用 A 的结果发出，不重试。
   - 回答本身很短（不超过 300 字），A 的结果几乎就是原文，不调用模型。
3. 「等授权 / 等回答」**不需要总结回答**，直接用屏幕上读到的问题和选项（现在已经能读到），即时发出，不能因为等摘要耽误。
4. 「中断 / 未执行 / 出错」用固定模板，加上中断前做到哪一步（最后一个工具调用的名字和参数开头），不调用模型。
5. B 的调用方式：`claude -p --model claude-haiku-5-5 --no-session-persistence --setting-sources "" --tools ""`。
   - 不留会话记录（不会出现在存档里）。
   - 不读你的用户设置（不触发你配置的 hooks，比如 Stop hook）。
   - 不给任何工具。
   - 本机已实测这组参数能用订阅登录正常运行。
   - 同时最多跑 2 个，其余排队；一个会话 10 分钟内重复结束只摘要一次。
6. **设置项**：「通知总结：只用规则 / 规则 + Haiku（默认）」；再加一个「外部会话也调用模型摘要」，默认关，只对舰桥启动的 agent 调用，控制费用。

C 不作为默认：会改变每个 agent 的回答写法，而且外部会话用不了。如果以后发现 A+B 对某类回答总结得不好，可以再作为选项加上。

### 3.3 总结的固定格式

内部统一生成一个结构，各渠道各取所需：

```
kind:    done | ask | permit | question | interrupted | never_ran | error
title:   一句话结论（≤ 30 字）
did:     做了什么（≤ 80 字）
result:  结论 / 结果（≤ 120 字）
needs:   需要你做什么（没有就空；≤ 80 字）
detail:  原文（主控用，最多 1500 字，截头尾）
```

### 3.4 各渠道怎么显示、怎么裁剪

裁剪一律在句子边界（。！？；或换行）截断，截断处加「…」。不在半个词或半个路径处截。

| 渠道 | 标题 | 正文 | 上限 |
|---|---|---|---|
| Windows 桌面通知 | `图标 名字 分类：title` | `result`；有 `needs` 时另起一行「需要你：…」 | 标题 60 字；正文 150 字（约 4 行） |
| 小窗列表、指挥中心任务列表 | 同上 | 一行 `title`；悬停或展开显示 did / result / needs | 一行；展开后 300 字 |
| 手机页 | 同上 | did + result + needs | 300 字 |
| 主控【舰桥通知】 | 现有格式，开头加一行「图标 分类：title」 | 「做了什么 / 结论 / 需要你」三行，再附 `detail` 原文（主控要据此行动，原文保留） | 总结 300 字 + 原文 1500 字 |
| 手机推送（ntfy） | 见下 | 见下 | 见下 |

**手机推送的取舍（需要你选）**：ntfy 的消息会经过 ntfy.sh 的公共服务器。话题名是长随机串，不公开，但内容在对方服务器上是明文，默认缓存 12 小时。

- **a. 保持现状**（0.9.42 起不再是默认，可在设置里选）：只发分类和项目名，如「🟡 newpad 完成，等你决定」，不发内容。看内容就点通知打开手机页（手机页本身在局域网里，有登录保护）。
- **b. 发总结（0.9.42 起默认）**：标题加 `title`，正文 result + needs，最多 250 字。不发原文。
- **c. 发总结，但服务器换成自建的 ntfy**（设置里可以填自己的服务器地址，现在已经支持）。

推荐 a 作为默认，在设置里可以改成 b，打开时提示「总结内容会经过 ntfy 服务器」。

## 6. 需要你确认的事

> **改动（2026-11-06，0.9.42）：手机推送改为 b，默认带结论。** 用户反馈只发「完成，等你决定」看不出要决定什么。现在标题是「图标 + 项目名 + 结论」，正文先写「需要你：…」，再写结果，最多 250 字，不发原文；a（只发分类和项目名）保留为设置里的可选项。同时收紧 🟡 的判定：只有回答里明确要你做选择、确认或操作时才算（问你的问句、请你做某事、「需要你做的」标题下的第一条），「是否」出现在陈述句里、测试结果、引号里的话都不算；「需要你」写成单独能看懂的一句（太短的问句带上前一句）。用当天 279 条真实回答回归：规则判为 🟡 的从 96 条降到 68 条。

> **用户决定（2026-11-06）：全部按推荐。** 1）A 规则截取打底 + Haiku 增强；2）外部会话不调用 Haiku，只用规则；3）手机推送选 a，不带内容，只发分类和项目名；4）桌面通知改为本轮一结束就弹，最多等 15 秒摘要。1~3 在 0.9.34 已是默认设置；4 在 0.9.38 实现（按会话记录判断本轮已结束）。
